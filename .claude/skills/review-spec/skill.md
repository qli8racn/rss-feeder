# review-spec

仕様書（requirements.md / design.md / tasklist.md）を読み込み、文書品質を整える。

## 手順

1. 対象ファイルを Read で取得する（`docs/steering/<phase>/` 配下）
2. 以下の観点でレビューする

   ### 冗長な記述の削除
   - 同じ内容を言い換えただけの繰り返しがないか
   - 自明な説明（「〜とは〜である」等）が含まれていないか

   ### 矛盾点のチェック
   - requirements.md と design.md の間で相反する記述がないか
   - 同一ドキュメント内で前後の記述が矛盾していないか
   - tasklist.md の完了状態と実際の実装・設計の記述が乖離していないか

   ### 報告フォーマットの統一
   - 見出しレベルが一貫しているか（h1/h2/h3 の使い方）
   - チェックリスト形式（`- [ ]`/`- [x]`）が正しく使われているか
   - 用語が統一されているか（例：「ユーザー」と「user」が混在していないか）

3. 結果を以下の形式で報告する

   ```
   ## 仕様書レビュー結果

   ### 冗長な記述
   - [問題あり] requirements.md L12: 〜の記述は L8 と重複
   - [OK] 問題なし

   ### 矛盾点
   - [問題あり] requirements.md の「〜」と design.md の「〜」が相反する
   - [OK] 問題なし

   ### フォーマット統一
   - [問題あり] design.md: 用語「記事」と「article」が混在（L5, L20）
   - [OK] 問題なし

   ---
   総評: X 件の問題が見つかりました。（または「問題は見つかりませんでした。」）
   ```

4. 修正が必要な場合は Edit で直接修正するか、修正案を提示してユーザーに確認する

## 注意

- 内容の正確性（仕様の妥当性）は判断しない。文書品質のみを対象とする
- 存在しないファイルは対象外とする
