# フェーズ：フィード追加時の自動取得・要約

## 概要

現在、フィードを追加（`add-feed` CLI / `POST /api/feeds`）すると、フィード URL が DB に登録されるだけで、
記事の取得（`fetch`）は別途ユーザーが `fetch` コマンドや `POST /api/articles/fetch` を実行するまで行われない。
同様に要約・カテゴリ付与（`enrich`）も別途 `rss-agent enrich` コマンドの実行が必要。

本フェーズでは、フィード追加が成功した直後に、そのフィードの記事取得を自動的に行う。
さらに `rss-feeder`（CLI）に限り、取得した新規記事に対する要約・カテゴライズ（`enrich`）も自動的に行う。

## 処理フロー（概要）

1. 入力 URL をフィード URL に解決（既存の `ResolveFeedURLUsecase`、変更なし）
2. フィードを DB に登録（既存の `AddFeedUsecase`、変更なし）
3. **（新規）** 登録したフィードの記事を取得・保存（既存の `FetchUsecase` を、登録した1フィードのみに対して呼び出す）
4. **（新規・`rss-feeder` CLI のみ）** 3で新規保存した記事があれば、そのフィードの新規記事のみを対象に要約・カテゴライズを
   `bin/rss-agent enrich --feed <url> --force --limit <n>` としてサブプロセス実行する

3, 4 はいずれも同期的に実行する（非同期・バックグラウンド実行は行わない。CLI も Web も、コマンド/リクエストが
完了するまでに完了する）。

## アーキテクチャ上の制約

- `docs/steering/20260619_feed_url_discovery/` の改訂（2026-06-20）で、Anthropic SDK に直接依存するのは
  `cmd/agent`（`bin/rss-agent`）のみという方針に統一した。本フェーズもこれに従う。
- `cmd/web`・`cmd/rss-feeder` はいずれも Anthropic SDK に直接依存しない。要約・カテゴライズ（`enrich`）は
  Claude を直接呼ぶ機能のため、`cmd/rss-feeder` から自動実行する場合も `bin/rss-agent enrich` を
  **サブプロセスとして実行**する（`discover-feed` と同じパターン。`internal/driver/feeddiscovery/subprocess.go` 同様の
  サブプロセス実装を `enrich` 向けに新設する）。
- **自動 enrich は `cmd/rss-feeder`（CLI）限定**とし、`cmd/web` では行わない（Web UI から追加したフィードは
  記事取得のみ自動化され、要約・カテゴライズは従来通り `rss-agent enrich` を別途実行する運用とする）。
  これは技術的制約ではなく、今回の要望範囲をCLIに絞るという判断であり、`cmd/web` 向けのサブプロセス機構自体は
  将来的に追加可能（スコープ外として明記する）。
- 自動 fetch（3）は Anthropic SDK に依存しないため、`cmd/web`・`cmd/rss-feeder` の両方で実行する。

## エラーハンドリング方針

- フィード登録（`AddFeedUsecase`）自体が失敗した場合は既存通りエラーを返す（変更なし）。
- 登録成功後の自動 fetch・自動 enrich は **best-effort**。失敗してもフィード登録自体の成功レスポンス・終了コードは変えない。
  失敗内容はログ（CLIは標準エラー出力、Webは `log.Printf`）に記録するのみで、呼び出し元には伝播させない
  （フィード URL の解決時点で既に「RSS/Atomとして解釈可能」であることは確認済みのため、登録直後の fetch が
  失敗するのは一時的なネットワーク不調等のレアケースと想定し、ユーザー体験上はフィード登録の成功を優先する）。
- 自動 fetch で新規保存記事が 0 件（取得成功したが全件重複等）の場合、自動 enrich はスキップする
  （対象記事が無いため Claude 呼び出しの必要がない）。
- `bin/rss-agent` が存在しない・実行できない場合も best-effort の対象とする（フィード登録自体は成功させ、
  enrich 失敗のログのみ残す）。

## スコープ外

- 非同期・バックグラウンド実行（goroutine 等によるレスポンス後の継続処理）
- 自動 enrich を無効化するオプトアウトフラグ・リクエストパラメータ
- 将来のマルチユーザー化を見据えた、定期バッチ実行によるコスト最適化（現時点ではシングルユーザー・学習目的の
  スコープであり、今回の要望自体が「追加時の即時反映」を求めているため対象外。必要になった時点で別フェーズとして検討する）
- `cmd/web` 向けの自動 enrich（サブプロセス機構自体は新設するが、`cmd/web` からは利用しない）

## 受け入れ条件

### `add-feed <url>`（CLI）

- 実行後、`list` コマンドで該当フィードの記事が要約・カテゴリ付きで確認できる（取得・enrich とも成功した場合）
- フィードの記事取得に失敗する場合（一時的なネットワーク不調等）でも、フィード登録自体は成功し、
  `登録しました: <url>` が出力される（fetch 失敗の警告は標準エラー出力に追加で出る）
- `bin/rss-agent` が見つからない場合でも、フィード登録・記事取得は成功する（enrich 失敗の警告のみ標準エラー出力に出る）
- 既存の `rss-agent enrich --force`（`--feed` 未指定で全件対象）の動作は変更されない（後方互換）

### `POST /api/feeds`（Web API）

- レスポンス内容・ステータスコードは既存と同じ（`Feed` DTO・`201`）。記事取得の成否はレスポンスに含めない
  （`Feed` スキーマは変更しない）
- フィードの記事取得に失敗する場合でも、フィード登録自体は `201` で返る
- 要約・カテゴライズは自動実行されない（アーキテクチャ上の制約を参照）
